你的任務是生成一個包含**函數缺失**情境的多輪函數調用對話。在這個情境中，用戶會要求助手執行一個需要目前工具列表中**不存在**的函數的任務。助手必須識別出所需的函數缺失並通知用戶。然後，用戶會提供缺失的函數定義，助手才能繼續執行。

首先，檢視以下資訊：

<scenario>
{{scenario}}
</scenario>

現在，熟悉可用的函數：

<functions>
{{function_schemas}}
</functions>

以下函數最初會**缺失**於工具列表中，但稍後會由用戶提供：

<missing_function>
{{missing_function}}
</missing_function>

生成對話時，請遵循以下指南：

1. 將對話格式化為一系列 <turn> 區塊。每個 <turn> 包含：
   - 恰好一個 <query>（用戶的訊息）
   - 零對或多對 <function_call> 和 <tool> 標籤
   - 一個 <response> 標籤，包含助手的自然語言回應

2. **關鍵規則：函數調用要求**
   - 對於任何用戶詢問可以由**可用函數**處理的資訊或操作的回合，助手**必須**進行函數調用。如果有函數可以提供資訊，**不要**只用自然語言回答。
   - 助手**只有**在以下情況才能純用自然語言回應（不調用函數）：
     a) 用戶的請求需要使用**缺失的函數**（「缺失」回合）- 在用戶提供函數之前
     b) 用戶只是在閒聊、感謝或道別
   - **重要**：當用戶提供缺失的函數定義後，助手**必須立即調用**該新提供的函數來完成原本的請求

3. **函數缺失回合要求：**
   - 恰好**一對**回合必須展示「函數缺失」情境
   - 在這對回合的**第一個**回合：用戶詢問**特別需要**缺失函數才能完成的事情（不是任何可用函數能處理的）
   - 助手識別出無法完成請求因為所需的函數缺失，並請求用戶提供
   - 在**第二個**回合：用戶提供函數定義（**使用 JSON schema 格式**，與 tool list 相同格式）
   - 助手接著調用新提供的函數

4. 函數缺失回合的結構應該如下：

<turn>
<query>
[用戶詢問**特別需要**缺失函數的事情 - 這個請求無法由任何可用函數完成]
</query>
<response>
[助手解釋無法執行這個**特定**任務因為所需函數不可用，並請求用戶提供。具體說明缺少什麼功能。]
</response>
</turn>

<turn>
<query>
[用戶使用 JSON schema 格式提供缺失的函數定義，例如：]

好的，這是函數定義：
```json
{
  "name": "function_name",
  "description": "函數描述",
  "parameters": {
    "type": "dict",
    "properties": {
      "param1": {"type": "string", "description": "參數描述"}
    },
    "required": ["param1"]
  }
}
```
</query>
<function_call>
missing_function_name(param1=value1, ...)
</function_call>
<tool>
[缺失函數的預期輸出]
</tool>
<response>
[助手確認收到函數，執行它，並提供結果]
</response>
</turn>

5. **一般回合（非缺失回合）必須使用函數調用。** 正確的一般回合範例：

<turn>
<query>
[用戶詢問會議詳情]
</query>
<function_call>
get_meeting_details(meeting_id=123)
</function_call>
<tool>
{"meeting_id": 123, "participants": ["王小明", "李美玲"], ...}
</tool>
<response>
[助手總結函數輸出的會議詳情]
</response>
</turn>

6. 目標是 {{total_turns}} 個總回合。函數缺失情境應該自然地發生在對話中間（不是在最開始）。

7. 對於每個 <response>，撰寫一個有幫助的自然語言總結，應該：
   - 直接回答用戶的問題
   - 總結工具輸出的關鍵資訊（當有調用函數時）
   - 保持友善和專業的語氣
   - 必須使用繁體中文撰寫

8. 保持對話的一致性，使用先前函數調用的資訊來指導後續的查詢和調用。

記住：
- 一般回合 = **必須**有函數調用（除非只是閒聊/問候）
- 缺失回合 = **沒有**函數調用，因為所需函數還不存在
- 用戶提供函數後 = **必須調用**新提供的函數來完成任務

重要提醒：
- 所有用戶查詢（<query> 內容）必須使用繁體中文撰寫
- 用戶名稱應使用中文名字（例如：王小明、李美玲、陳大偉）
- 保持在給定情境和領域的上下文中

將你的整個回應輸出在 <dialogue> 標籤內，包含多個如上所述的 <turn> 區塊。
